# Panda 接触抓取、抬升与持物核验

本轮对应实施文档 01 的步骤 3 前半段。目标是复用上一轮的末端控制，完成接近、下降、夹持、抬升与持物核验。

## 一次运行完整观察

双击本目录的 `open.cmd`，点击 3D 窗口后使用主键盘。

| 按键 | 操作 |
|---|---|
| `1` | 复位后运行标准抓取 |
| `2` | 复位后运行偏移抓取，观察空抓 |
| `3` | 复位后以较低夹爪力限运行，观察抬升失败 |
| `O` | 松开夹爪，观察物体失去夹持后落下 |
| 空格 | 暂停或继续仿真 |
| `C` | 取消当前流程，保持当前关节目标与夹爪命令 |
| `R` | 恢复 home 与方块初始状态，进入暂停 |
| `F` / `V` | 聚焦夹爪并跟随 / 恢复总览 |
| `Q` | 退出并保存汇总 |

建议先按 `1` 看完整流程，再按 `O` 观察释放，最后比较 `2` 和 `3`。
每次选择案例都会明确复位，旧的执行先记录终态，新执行使用独立 execution_id 和新的 epoch。
取消后可以用 `O` 释放当前夹持，也可以用 `R` 恢复起点。

## 每个阶段为什么存在

| 阶段 | 实现什么 | 为什么需要 | 进入下一阶段的依据 |
|---|---|---|---|
| approach 接近 | 夹爪到方块上方 12 cm | 提供可解释的接近航点 | 实际末端位姿到位并稳定 |
| descend 下降 | 夹爪下降到方块两侧 | 把物体置于双指之间 | 实际末端位姿到位并稳定 |
| close 闭合 | 发送夹爪闭合目标 | 通过接触产生夹持作用 | 双指有效接触连续维持 0.15 秒 |
| lift 抬升 | 保持夹爪命令，末端上移 12 cm | 检查物体能否随夹爪离开桌面 | 抬升到位，接触持续有效 |
| verify_hold 核验 | 检查接触、高度和相对稳定 | 用物理证据确认持物效果 | 核验条件连续成立至少 0.5 秒 |
| held 已验证 | 保存本次抓取结果，持续显示当前状态 | 为后续搬运提供结果和证据 | 操作者继续观察、释放或开始下一次实验 |

这是一个有限状态机。每个阶段都有进入条件、动作、完成条件和超时，阶段切换会写入事件。
出现到位失败、非预期碰撞、接触丢失或核验超时，会进入明确的失败终态。

## 物理场景与控制

Panda 继续采用固定版本的官方模型。项目在内存中组合桌面、桌腿和红色自由方块。

- 桌面高度为 0.20 m。
- 方块边长为 0.04 m，质量为 0.08 kg。
- 方块具有自由关节，位置、朝向与速度随物理过程变化。
- 官方模型已有的双指联动约束用于夹爪机构。
- 抓取通过执行器、接触和摩擦形成，物体保留自由运动状态。
- 启动清单记录本轮新增的物体附着约束数量为 0。

末端运动仍调用上一轮的 `PandaArm.start/update`。位置与朝向进入 IK，再经过路径检查和平滑关节轨迹，由原位置执行器驱动物理运动。
新增的 `set_gripper` 接收总开度，范围为 0—0.08 m，转换为官方 0—255 控制映射。
本轮修订使夹爪命令在抬升过程中持续保持，因此末端运动与夹持可以同时进行。

## 需要掌握的接触技术

**法向力**是接触表面沿法线方向相互挤压的力。窗口的 Contact L/R 显示两侧接触的法向力总和。

**摩擦力**能够沿接触表面抵抗相对滑动。粗略以库仑摩擦理解，单侧可用的切向作用受 `μ × 法向力` 限制。
方块重量约为 `0.08 × 9.81 = 0.785 N`，双指需要提供足够的支撑作用才能抬起它。

**夹爪力限**限制执行器的驱动力。它与实际接触力分别记录，传动关系、关节状态和接触动力学共同影响实际力。
标准案例沿用官方 100 N 执行器力限，弱夹持案例设为 0.3 N。

**接触求解**会影响静止夹持时的微小滑动。本轮长时间检查发现默认软接触存在缓慢滑移，桌面场景采用 5 次 noslip 静摩擦后处理迭代进行校准。
校准后另做了 30 秒持物检查。该求解设置写入场景配置清单，上一轮 reach 场景继续使用其原始场景设置。

方块接触参数采用较高的接触优先级，使其配置的摩擦系数成为与手指和桌面接触时的有效系数。
摩擦系数为 0 时使用纯法向的一维接触，正摩擦使用包含法向及两个切向约束的三维接触。这使零摩擦配置拥有明确的物理含义和稳定的数值表现。

## 程序依据什么宣布抓取成功

独立的 `GraspVerifier` 读取实际物理状态，持续检查以下条件。

1. 左右手指都与方块存在有效接触，每侧法向力至少 0.02 N。
2. 方块最低点离桌至少 5 cm。计算包含方块旋转后的实际竖直包围范围。
3. 方块相对 TCP 的位置漂移在窗口内不超过 3 mm，朝向漂移不超过 0.1 rad。
4. 这些条件连续维持至少 0.5 秒。

TCP 是夹爪的工具中心参考点。相对位置表示“从随夹爪运动的坐标系看，方块在哪里”。
稳定持物时，方块和夹爪一起移动，相对位姿保持稳定。

窗口中的关键字段如下。

| 字段 | 怎样理解 |
|---|---|
| Phase | 当前执行阶段 |
| Result | 本次抓取流程的运行或终态 |
| Cube bottom clearance | 方块最低点相对桌面的高度 |
| Finger contact L/R | 左右手指的有效接触力 |
| Finger opening | 两根手指的实际总开度 |
| Relative drift | 当前稳定窗口中的相对位置漂移 |
| Stable window | 连续满足条件的时间 |
| Holding now confirmed | 当前持物证据是否满足核验规则 |
| Release requested | 操作者是否已明确要求松开 |
| Unrequested holding loss | 抓取完成后是否出现未经释放请求的持物丢失 |

Result 保存抓取任务在核验窗口完成时的结论，Holding now confirmed 持续反映当前事实。
按 `O` 后会保存释放事件，接触解除后当前持物确认变为 false，方块受重力落下。已保存的抓取结果仍能用于复盘此前的核验过程。
抓取完成后出现非主动释放的支撑丢失，会产生单独的 `holding_lost_after_completion` 事件和可见提示。

## 三个案例怎样解释

标准抓取用于观察完整闭环和核验依据。

空抓案例把接近位置沿 Y 方向偏移 9 cm。夹爪可以闭合，物体仍留在桌面，最终返回 `no_bilateral_contact`。

弱夹持案例保持相同目标与物体，只降低执行器力限。本次记录中，闭合阶段形成接触，进入抬升后双侧接触丢失，最终返回 `holding_contact_lost`。

案例通过相同控制器、状态机和判定器运行。差异来自保存的实验条件。

## 配置、记录与感知假设

参数位于 `configs/tasks/panda_grasp.json`。`scene` 可配置方块位置、质量、尺寸、摩擦与桌面尺寸，默认值由运行清单完整导出。

每次启动在 `runs/panda_grasp/<run_id>/` 保存清单、事件、CSV 采样与汇总。
事件包含每个阶段、运动目标、IK 误差、案例条件、终态、释放与持物丢失。
CSV 包含接触力、实际开度、离桌高度、相对漂移和稳定时间。

本轮接近目标使用明确标注的 `simulated_state_sensor_v0_exact_pose`，由仿真提供方块位姿。核验读取仿真真值。
技能入口显式接收物体位置，后续 02 将通过观测适配器提供该输入，并完善信息隔离。

无界面运行使用相同运行时，命令为 `python -m decision_lab grasp --headless --scenario normal`。
将 scenario 改为 empty 或 weak 可以得到对应失败记录，任务失败时命令退出码为 1。
使用前需要设置项目 `src` 模块路径和本机 MuJoCo 解释器，`open.cmd` 已处理窗口启动的这两项配置。

本轮验证摘要见 `validation.json`。搬运、放置、浏览器工作台和 01 的完整 A01—A04 验收继续按阶段计划推进。
