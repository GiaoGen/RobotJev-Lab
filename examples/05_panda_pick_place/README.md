# Panda 完整抓取、搬运与放置

本轮完成实施文档 01 步骤 3 的完整物理任务，继续复用前两轮的末端控制和接触抓取。
任务终态由放置核验决定，运行链路为接近 → 下降 → 闭合 → 抬升 → 持物核验 → 搬运 → 放置下降 → 松开 → 撤离 → 放置核验。

## 一轮完整体验

双击 `open.cmd`，点击 3D 窗口后使用主键盘。

| 按键 | 案例或操作 |
|---|---|
| `1` | 复位后完成抓取、搬运与放置 |
| `2` | 把黄色障碍放入路径，检查载物路径的拒绝原因 |
| `3` | 在搬运中降低夹持力，观察滑移、掉落与失败 |
| 空格 | 暂停或继续 |
| `C` / `R` | 取消 / 恢复初始状态 |
| `O` | 明确请求松开夹爪，并取消正在执行的任务 |
| `F` / `V` | 聚焦夹爪 / 恢复总览 |
| `Q` | 退出并保存记录 |

红色是搬运方块，蓝色是目标托盘，黄色是路径障碍，紫色是禁触物体。
每个案例通过同一运行时执行，案例切换会复位并记录旧任务终态。

建议先看完整的 `1`，再比较 `2` 的执行前拒绝与 `3` 的执行中失败。
按 `3` 后夹持力的变化来自明确登记的试验事件，发生时机、变化前后力限和物理后果都写入记录。

## 新增部分分别解决什么问题

| 部分 | 技术与实现 | 原因 |
|---|---|---|
| 持物运动目标 | 使用方块相对 TCP 的实测位姿，把物体目标位置换算为 TCP 目标 | 让方块对准托盘内部 |
| 载物路径检查 | 在独立计算状态中，沿候选关节轨迹更新机器人和所持方块的几何位姿 | 检查整组运动几何是否会碰撞 |
| 搬运中监督 | 持续检查双侧接触、相对滑移、实际碰撞和禁触约束 | 及时结束失去持物条件的动作 |
| 放置下降 | 在托盘上方下降到可释放的高度 | 限制释放后的下落距离 |
| 松开与撤离 | 检查实际开度、接触解除和夹爪离开物体的距离 | 确认物体已独立留在目标区域 |
| 独立放置核验 | 检查物体整体范围、支撑、速度和稳定窗口 | 为任务结果提供物理证据 |

## 为什么要把方块纳入路径检查

本轮默认障碍案例中，单独检查机械臂会通过。把手中的方块一起纳入检查，会发现 `collision:cube/path_obstacle`。
这展示了末端能够到达目标之后，仍需要核对搬运物体的体积与路径。

程序在抓取后测量方块相对夹爪的位姿。
设夹爪的旋转为 R、位置为 p，方块在夹爪坐标系中的位置为 r，则预测的方块世界位置为 `p + R × r`。
每个关节采样点都通过 FK 更新夹爪，再用这个关系更新计算状态中的方块，执行碰撞检查。

这个投影发生在独立的 `planning_data` 中。实际世界中的方块继续保留自由关节，由夹持接触和摩擦带动。
物理仿真持续核对实际接触与滑移，补充离散路径采样的检查。
关节采样分辨率仍由 `path_sample_rad` 配置，默认最大关节间隔 0.025 rad。

## 两条可核对的航点路线

`open.cmd` 使用直接到托盘上方的路线。
`detour.cmd` 使用两个额外航点，先经过 X=0.58、Y=-0.05，再经过 X=0.58、Y=0.18，最后到托盘上方。

在绕行入口中按 `2`，同一个障碍案例能够沿配置的侧向航点完成任务。
这是操作者明确选择的路线配置。控制器、夹爪、物理参数与结果判定共用同一实现。
后续 02 可以把路线作为候选技能参数提供给 Harness 和决策层。

两条配置分别位于 `configs/tasks/panda_pick_place.json` 和 `configs/tasks/panda_pick_place_detour.json`。
`placement.carry_via_xy_m` 保存中间航点，目标托盘位置由 `target_center_xy_m` 配置。

## 什么时候才算放置成功

`PlacementVerifier` 从实际物理状态检查以下条件，并要求连续保持至少 0.5 秒。

1. 方块的整个水平投影位于目标区域内，包含方块旋转后的范围。
2. 托盘底板提供有效支撑，方块底面高度与托盘表面相符。
3. 物体线速度低于 0.02 m/s，角速度满足配置上限。
4. 夹爪实际开度达到释放要求，手指有效接触解除。
5. 夹爪已从物体上方撤离至少 6 cm。
6. 本次任务没有触发禁触约束。

物体中心进入区域、物体仍悬在空中、夹爪仍接触、撤离未完成或物体仍在滑动，都会导致核验条件不完整。
禁触违规会在本次任务中持续保留，直到完整复位才清除。

托盘具有真实底板与边缘碰撞几何。允许放置时方块与托盘底板接触，具体许可按 geom 对定义。
这使托盘底板的支撑接触与其他障碍接触拥有明确的检查范围。

## 搬运中掉落案例

案例 `3` 先完成相同的抓取和抬升。
进入搬运阶段 0.35 秒后，预设试验把夹爪执行器力限从 100 N 降到 0.1 N。
实际相对滑移触发 `payload_slipped` 后，运动结束并记录失败，方块继续受重力和接触影响。

物理后果会继续显示，任务结果保持这次失败的历史结论。
复位会恢复初始物体状态、控制量、正常力限、载物规划引用、时间窗口和违规记录。

## 代码如何衔接

| 文件 | 职责 |
|---|---|
| `robots/panda.py` | 复用 IK、轨迹、夹爪控制，增加载物几何投影与接触许可 |
| `robots/panda_grasp.py` | 复用已验证的抓取与抬升技能 |
| `robots/panda_pick_place.py` | 组合抓取、搬运、释放、撤离与任务终态 |
| `simulation/placement.py` | 托盘场景、独立放置核验与禁触记录 |
| `grasp.py` | 共用仿真状态持有、命令、暂停、复位与记录生命周期 |
| `pick_place.py` | 组装本任务的场景、技能、核验器和案例条件 |
| `pick_place_viewer.py` | 显示本轮阶段与核验证据 |

任务组装通过已有运行时的明确构建入口复用物理步进，两个任务共享原生显示和记录。
浏览器接入时可以继续调用同一实验核心，无界面评测已使用相同入口。

## 运行证据与当前假设

每次启动会生成 `runs/panda_pick_place/<run_id>/`。
清单包含完整配置、物理与控制参数、模型提交、代码哈希和初始状态。
事件包含载物路径检查、预测相对位姿、关节目标、阶段转换、力限干预及任务终态。
CSV 按 epoch、execution_id 和物理步编号关联支撑力、速度、释放、撤离与稳定窗口。

物体目标输入继续采用明确标注的仿真精确位姿；结果核验读取仿真真值。
后续 02 将在已有技能入口接入观测适配、能力前置条件、候选与分层决策。

无界面运行示例为 `python -m decision_lab pick_place --headless --scenario normal`。
blocked、drop 案例在默认路线下返回任务失败退出码 1。启动脚本已设置本机解释器和模块路径。
本轮检查摘要见 `validation.json`。01 的浏览器工作台、独立环境锁定及 A01—A04 全项验收继续推进。
