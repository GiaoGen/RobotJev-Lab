# Panda 三个末端目标到位

本实验对应实施文档 01 的步骤 2。任务是给出夹爪的位置和朝向，让程序求解并执行关节运动，再用实际物理状态确认到位。

## 运行与连续探索

双击本目录的 `open.cmd`，它会打开 MuJoCo 原生查看器和输出运行信息的控制台。
本轮使用官方 `mujoco.viewer` 的原生查看器，运动控制由项目 Python 程序推进。
窗口初始暂停在 home 姿态。点击 3D 视窗后，用主键盘操作。

| 按键 | 操作 |
|---|---|
| `1`、`2`、`3` | 分别执行目标 A、B、C，接受后自动开始运行 |
| 空格 | 暂停或继续物理时间 |
| `R` | 恢复 home，清理当前运动，进入暂停 |
| `C` | 取消当前运动，发送当前关节位置的保持目标 |
| `Q` | 退出并保存运行汇总 |

运动完成后可以继续选择下一个目标。执行中收到新的目标会显示 `busy`，取消后可以重新选择。
取消后物理速度仍会经历减速和稳定过程。暂停会停止物理时间。
相机可用鼠标拖动旋转、滚轮缩放。

## 看懂目标和画面

目标坐标位于世界坐标系，单位为米。官方模型的基座参考系与世界参考系在此场景中重合。

| 按键 / 目标 | X | Y | Z | 夹爪朝向 |
|---|---|---|---|---|
| 1 / A | 0.45 | -0.12 | 0.35 | 指向下方 |
| 2 / B | 0.45 | 0.12 | 0.35 | 与 A 相同 |
| 3 / C | 0.50 | 0.00 | 0.50 | 指向下方，水平朝向相对 A/B 改变约 90° |

金色球标记三个目标位置。夹爪指尖之间的绿色球表示 TCP，即本实验选定的工具中心点。
TCP 位于官方 hand 刚体局部 Z=0.1034 m，依据手指根部与指尖接触垫的位置选取。
它作为运动参考点，后续接触抓取时需要结合物体尺寸验证。

RGB 箭头分别表示 X、Y、Z。
基座处是世界坐标轴，夹爪处是实际 TCP 坐标轴，当前目标处的较长箭头表示目标坐标轴。
目标朝向用 `xyzw` 四元数保存，进入 MuJoCo 时转换为 `wxyz`。

## 用一个完整过程理解控制链

按 `1` 后，程序依次完成以下工作。

1. 读取目标 A 的位置与朝向。
2. 从实际关节位置出发，在独立计算状态中求解 IK。
3. 检查关节限位与关节插值路径的碰撞。
4. 把关节目标沿平滑轨迹发送给官方位置执行器。
5. MuJoCo 根据执行器、重力、惯量和约束推进物理状态。
6. FK 从实际状态计算 TCP 位姿。
7. 实际误差和关节速度满足稳定窗口后，状态变成 `succeeded`。

| 技术 | 具体解决的问题 | 在实现中的位置 |
|---|---|---|
| 位姿 | 同时描述 TCP 的位置和朝向 | `PoseTarget` |
| FK 正运动学 | 从实际关节状态求 TCP 位姿 | `mj_forward` 与 `site_xpos/site_xmat` |
| IK 逆运动学 | 从目标位姿求一组关节目标 | `PandaArm.solve_ik` |
| Jacobian | 近似描述关节小幅变化对 TCP 的影响 | `mj_jacSite` 返回位置与旋转 Jacobian |
| 阻尼最小二乘 | 限制病态构型附近过大的求解步长 | `J.T @ solve(J @ J.T + damping² I, error)` |
| 关节轨迹 | 让多个关节连续、平滑地接近目标 | 五次 smoothstep 插值 |
| 偏置力前馈 | 补偿重力等模型偏置力，减小实际跟随误差 | `qfrc_bias / position_gain` 转成小幅控制目标偏移 |
| 物理到位核验 | 根据实际 TCP 位姿确认动作效果 | 实际位姿误差、关节速度、稳定窗口 |

IK 的六维误差由三个位置误差和三个旋转误差组成，七个机械臂关节参与求解。
旋转误差与旋转 Jacobian 都使用世界参考系。
姿态部分以 0.25 m/rad 的权重参与位置与朝向的联合求解。
每轮关节增量限制在 0.1 rad 以内，最多执行 250 次迭代，关节目标保留限位余量。
数学求解使用独立 `MjData`，运动中的 `MjData` 由运行时持有。

五次插值的起点和终点速度、加速度为零。轨迹时长根据最大关节变化和 0.6 rad/s 的目标速度上限计算。
偏置力前馈经过原位置执行器及其力限生效，控制目标同时接受关节范围约束。

## 看懂窗口里的两种误差

| 显示项 | 表示什么 | 能解释的问题 |
|---|---|---|
| `IK residual` | 求解出的关节角通过 FK 后，与目标位姿之间的误差 | 数学求解是否收敛 |
| `Physical error` | 实际运动中的 TCP 与目标位姿之间的误差 | 执行器和物理过程是否真正跟上 |

位置误差显示为 mm，朝向误差显示为 deg。
控制器先求解，再执行运动。因此运动开始时，IK residual 可以已经很小，而 Physical error 仍较大。
接近终点时，可以看到实际误差逐渐收敛。

本轮到位要求为位置误差不超过 5 mm、朝向误差不超过约 2°、最大关节速度不超过 0.05 rad/s，并连续保持 0.25 秒。
IK 的内部求解阈值更紧，为 0.2 mm 和 0.002 rad。
超时或碰撞会产生明确终态，原因显示在窗口并写入事件。

路径碰撞检查在关节空间按最大 0.025 rad 增量采样，检查当前模型启用的碰撞对。
执行期间每个物理步检查接触穿透和关节限位。该实现服务于当前三个空载目标，后续桌面搬运会增加任务接触规则与路径条件。

## 推荐的一轮观察，约五分钟

连续执行 A → B → C，重点看三个现象。

- A 到 B 的夹爪朝向相同，但多个关节会协调运动。
- 到 C 时，位置和朝向一起改变。
- 比较 IK residual 与 Physical error 的变化时间。

还可以在运动途中暂停再继续，或取消后复位。将这些现象沿控制链解释，会比单独记忆每个按钮更直接。

## 配置、代码与记录

目标位姿保存在 `configs/tasks/panda_reach.json`。修改后重新打开本实验，生效配置会写入本次运行清单。
单个目标可先改一个位置分量，例如 A 的 Y，从 -0.12 改成 -0.08，比较关节与 TCP 的变化。

建议按一次真实调用顺序阅读。

1. `src/decision_lab/native_viewer.py` 将按键放入队列。
2. `src/decision_lab/reach.py` 的 `select_target` 接受目标。
3. `src/decision_lab/robots/panda.py` 的 `start → solve_ik → check_path` 准备运动。
4. 同文件的 `update` 生成平滑关节目标与前馈。
5. `reach.py` 的 `advance` 执行物理步进和状态核验。
6. `snapshot` 提供实际状态，`recording.py` 保存证据，原生查看器显示状态。

算法和运行时通过普通 Python 调用协作，原生查看器负责按键与显示。后续浏览器、抓取状态机和无界面实验可以调用相同的控制代码。

每次打开都会生成独立的 `runs/panda_reach/<run_id>/`。

- `manifest.json` 保存实际配置、依赖版本、模型来源、代码哈希和初始状态。
- `events.jsonl` 保存目标接受/拒绝、IK 结果、运动终态、暂停和复位。
- `telemetry.csv` 保存仿真时间、实际 TCP 位置、误差与关节速度。
- `summary.json` 保存本次各次运动的结果。

无界面验证使用同一运行时，命令为 `python -m decision_lab reach --headless`。
调用前需要将项目的 `src` 加入 `PYTHONPATH`，并使用已有 MuJoCo 环境。
`open.cmd` 已配置本机解释器路径与模块路径。
