## 1. 要回答的五个问题

| 问题 | 对照方式 | 主要结论范围 |
|---|---|---|
| L2 模型带来什么效果 | 规则、低延迟模型、通用模型 | 两个受控场景中的任务完成、恢复和成本 |
| 快速判断有什么取舍 | 低延迟与通用模型使用同一接口 | 端到端延迟、有效响应比例、闭环结果和费用 |
| 分级恢复是否有效 | 固定重试或始终重规划，与局部恢复加按需升级比较 | 指定扰动下的恢复效果和重规划成本 |
| 主动能力探索是否有效 | 同试次数的主动、随机或固定扫描 | 能力预测质量、覆盖与在线影响 |
| 跨机器人共享有什么效果 | 共享策略配置与每机器人独立配置比较 | 共通问题表现和实际适配工作量 |

每个问题都保留方法定义、配置版本、原始结果和失败样本。效果方向由实验决定。

## 2. 学习要点

- 实验单位是完整回合或完整探索重复，统计时保留其关联结构。
- 配对实验让各策略从同一初始清单和扰动规范开始，轨迹分叉后继续使用各自实际观测。
- 消融通过改变一个机制检查其贡献，其他配置保持一致并记录差异。
- 开发集用于调参，独立测试清单在调参前固定，测试后的新改动形成新版本和新一轮评价。
- 成功率同时给出分子、分母、区间和测试条件。恢复率以确实出现恢复机会的回合为分母。
- 统计区间反映当前样本的不确定性，样本量不足时使用探索性表述。

## 3. 评测清单与预算

### 3.1 主实验

两种机器人各准备正常、局部扰动、计划失效、未见条件四组场景，每组先使用 10 个配对配置。三种 L2 策略共 `2 × 4 × 10 × 3 = 240` 回合，对应 80 个配对场景身份。

主实验对 L2 的比较固定 L3 初始计划、控制器、技能、能力版本和可见信息范围。每个场景的初始计划从同一合法任务生成并校验，计划文件与生成成本单独记录。运行中的按需重规划使用相同 L3 实现和配置。

另运行两机器人各 6 个自然语言端到端回合，检查解析、初始规划、决策和动作全链路，计入 12 回合。单独呈现完整链路结果及 L3 费用。

### 3.2 机制对照

| 实验 | 初始预算 | 冻结项 |
|---|---|---|
| 恢复机制 | 20 个机械臂扰动配置 × 2 方案，共 40 回合 | 同 L2、L3、控制器、扰动和总时限 |
| 能力表在线效果 | 20 个任务 × 2 能力配置，共 40 回合 | 同技能、决策器、感知与任务 |
| 共享与专用配置 | 每机器人 10 个共通情境 × 2 方案，共 40 回合 | 相同可观测信息与执行器 |
| 主动探索 | 沿用文档 04 的 480 次主试验与 240 次独立验证 | 相同控制器、预算和验证条件 |
| 移动能力 | 沿用文档 05 的约 40 次试跑 | 固定底盘与传感版本 |

闭环回合初始总预算为 372。能力探索和独立验证按试验次数另计，报告同时给出总执行量。试跑先测每回合平均步数、墙钟耗时、决策调用和费用，再登记全量估算。以上数量是工程预算，统计精度以最终区间体现。

共享配置在两机器人上使用同一提示结构、规则优先级与公共参数，专用配置允许分别在开发集调整语义说明或阈值。分别记录调整工时和配置变化。两类配置都保留机器人专用控制器。

### 3.3 模型预算

先从十个回合测得平均 L2 调用数、L3 调用数和 token，使用 `总费用 ≈ 各模型调用数 × 每次平均费用` 估算。保存价格来源和日期，使用实际计费单位。

正式模型实验设置显式费用与调用数上限。达到额度后将任务标记为预算中止，记录待运行清单。规则与离线报告可继续执行。价格和账户权限由实际配置确定。

## 4. 可复现与批量执行

每个评测配置包含 `scenario_id`、初始状态、任务、机器人、策略、模型、控制与能力版本、观测配置、种子、扰动触发、时限和指标版本。

1. 使用实际生效配置生成规范化 JSON 与哈希。
2. 每个配对场景分配独立的环境、观测、模型和扰动随机源。
3. 将相同环境配置复制给所有策略，固定扰动语义和模型采样参数。
4. 串行启动回合，复位后核对初始清单哈希。
5. 回合完成写终态和完整性，汇总器根据清单识别已完成与待运行项。
6. 中断后优先恢复待运行项，重复执行保留尝试编号和原失败记录。

模型服务可能存在版本变化与非确定性，保存确切模型标识、时间、原始响应和供应商信息。物理重现同时依赖引擎、平台、资产和数值配置，按指定容差比较轨迹与结果。

建议命令如下，配置在实施中创建并验收。

```powershell
uv run python -m decision_lab evaluate --config configs/evaluation/main.json
uv run python -m decision_lab evaluate --config configs/evaluation/main.json --resume
uv run python -m decision_lab report --evaluation main
```

## 5. 指标口径

| 指标 | 计算与记录要求 |
|---|---|
| 完成率 | 满足独立物理判定的回合数 / 全部启动回合数，另列基础设施故障与取消 |
| 时间 | 仿真完成时间、墙钟完成时间、暂停时间、模型等待分别记录 |
| 恢复率 | 成功恢复的机会数 / 真实出现恢复机会数，同时给出回合级结果 |
| 重规划 | 每回合 L3 修订次数、原因、延迟和费用 |
| 无效建议 | 非法候选、过期、条件违规、参数非法分别计数 |
| 约束事件 | 按预定接触对象、接触条件与有效窗口计数，给出每回合发生比例 |
| 决策延迟 | 排队、请求、解析、监督、应用全链路的 p50/p95 与超时率 |
| 费用 | 实际或估算金额、币种、token、价格日期，缺失用 null |
| 能力预测 | Brier 分数、可靠性图、边界错误、未知比例和覆盖率 |
| 适配成本 | 实际工时、新增/修改配置和文件、训练情况、公共接口修改 |
| 记录完整性 | 事件序号、关键字段、模型记录与终态完整情况 |

对成功回合耗时给条件统计，同时呈现失败和超时比例。任务总时限作为失败时间截断口径另行报告，具体定义写入指标版本。

模型自述分数的 Brier 分数只在明确预测事件、得到独立标签的样本上计算。能力表概率也按同一预测目标评价。样本不足的分箱合并或显示样本数。

成功率使用 Wilson 95% 区间。策略差异按 `scenario_id` 做配对 bootstrap，在同一采样中保留各策略结果。探索方法按独立探索种子评价，单次探索内的多个格保持关联。只有 3 个探索种子时，报告逐种子结果和较宽的不确定性。

## 6. 真实性与贡献审计

### 6.1 信息隔离

运行 B03 的等价观测双世界测试，检查提示、候选描述和能力特征。核验隐藏质量、摩擦、碰撞未来结果等字段只流向允许的路径。比较场景标签中是否带入成功答案。

### 6.2 Harness 贡献

统计候选过滤前后数量、唯一候选比例、过滤原因和由硬约束直接决定的事件。模型价值重点分析存在多个合理候选的决策点，同时报告全部回合。

### 6.3 候选顺序与模型脆弱性

在冻结的决策请求上交换候选顺序、改写等价表述、检查单位表达，并保留候选的原有语义。离线变化单独报告，再选择代表性案例运行真实闭环验证。

### 6.4 未见条件

预留目标位置组合、障碍布局、扰动时机或摩擦分布。传感器实际可见范围和任务支持范围保持声明清楚。分别报告正常、局部扰动、计划失效和未见条件，附上所有失败回合索引。

## 7. 报告、数据契约与 playground 接入准备

报告包含研究问题、方案定义、运行环境、配置与版本、样本量、指标、区间、成本、失败分类、代表事件、证据路径、适用范围和局限。

CLI 提供对照选择、进度、终态数量、指标和差异事件索引。每条结论追踪到配置、原始回合和统计代码，导出 Markdown、CSV 和静态图，标明单位、分母、区间和样本量。07 工作台查询同一产物和事件读取器。

图表至少包括分条件完成率、延迟与费用、恢复与重规划、能力误差随预算变化、能力边界图。每张图对应一个具体问题。

## 9. 个人理解检查

亲自从十个原始回合计算完成率，解释分母。选择一个模型优于规则的案例和一个相反案例，沿事件链说明原因。解释一次区间较宽的结果，以及当前样本支持的结论。

交接时提供评测配置、原始记录、统计程序、完整报告、费用清单、失败索引与版本化读取入口。文档 07 在接入条件具备证据后整合 playground，并完成 G04 一致性检查。

- Wilson 与比例区间。 [NIST](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)
- Bootstrap 实现与参数。 [SciPy bootstrap](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html)
- 原项目的泛化、偏差与失败讨论。 [robo-jev results](https://github.com/STEERIX-home/robo-jev/blob/main/docs/results.md)
