## 1. Playground 接入条件与最终验收对象

完整 playground 在本阶段实现。开工时检查 06 的 F01、F02、F07 及 [00 第 5.4 节](00_总实施路线图与技术决策.md#54-playground-的接入条件与一致性) 所列证据，确认真实任务、基线、模型对照、成功/失败记录、指标重建与版本化数据接口。记录已满足和待补项目，先修复影响接入的核心问题。

交付内容包括本地研究平台、两个不同形态的完整场景、能力探索、共享分层决策、执行监督、动态干预、真实记录、对照报告和准确的运行说明。A04 作为 01 转交项目在此补验，G04 验证 benchmark 接入一致性。

每项功能关联 FR、测试、运行证据和当前状态。最终报告按真实完成情况记录通过、部分完成、失败和未验证。第 8 周的求职材料使用已经验证的内容与实测数据。

## 2. 联调原则与关键知识

联调重点是跨模块的一致性，学习重点包括配置和版本管理、回归测试、性能分解、资源释放、故障恢复，以及如何用证据说明个人贡献。

每个问题先建立最小复现配置，再定位到输入、决策、控制、物理、核验或显示环节。修复后运行针对性测试与两场景固定回归，把变化记录到对应实现文档。

## 3. Playground 实施顺序

1. **真实记录读取与接口适配**。从 01 和 06 选择真实成功、失败记录，确认 schema、模型与依赖版本、单位、状态和完整性。API 直接调用既有读取/汇总逻辑，提供 run 清单、报告、事件检索和状态读取。
2. **历史结果页与差异事件**。先加载实测指标、能力图和失败索引，完成按 run/事件跳转。用同一输入重建 CLI 与页面结果并核对单位、分母和舍入。
3. **3D 资产与状态显示**。以实际模型导出可视网格、材质和局部变换，原始状态通过读取器重建世界位姿。核对坐标、四元数顺序和模型哈希，播放失败与缺口。
4. **实时控制与干预**。接入现有运行时、监督器、命令 ID 与 epoch，提供任务、暂停、复位、机器人/策略切换和三种扰动。回执和终态来自实验核心。
5. **探索与比较交互**。连接现有探索调度器与成对运行器，显示预算、试验、证据、结果和版本，用户操作进入相同核心入口。
6. **一致性、回归与体验收敛**。完成 A04 和 G01—G04，修复状态、数据和显示偏差，形成独立可用的两条路径。

接口遵循“命令提交 → 核心审核与执行 → 回执/事件 → 结果读取”。实验核心持有状态、核验与指标的权威实现，浏览器保存显示与交互选择。观测数据与显示/核验数据按既定权限序列化，模型输入从观测读取器构造。

## 5. 性能、稳定性与资源

### 5.1 测量口径

在文档 00 的本机环境上固定 1080p 浏览器窗口、默认场景和默认显示质量。记录电源模式、依赖版本、后台负载和测试时长。

| 项目 | 初始体验目标 | 测量方式 |
|---|---|---|
| 浏览器显示 | 稳定观察时中位帧率至少 30 FPS | 10 分钟采样，报告帧时间 p50/p95 |
| 仿真实时性 | 默认场景实时因子至少 1 | 仿真时间增量 / 活跃墙钟时间，暂停单列 |
| 状态推送 | 约 20 Hz，延迟与丢帧可见 | 快照序号、发送接收时间与队列长度 |
| 控制响应 | 本地暂停初始目标 p95 小于 200 ms | 命令接收至控制状态改变，分解网络与运行时 |
| 模型等待 | 显示等待，画面与停止入口持续响应 | 模型延迟注入时测前端和物理步进 |
| 内存 | 10 次复位与 10 次切换后无持续增长趋势 | 进程与浏览器内存曲线，保留峰值 |
| 长运行 | 连续交互 30 分钟并完成多回合 | 检查异常、资源释放和记录完整性 |

这些值是实施目标，最终支持规格填写实测。模型延迟同时报告服务响应和动作生效的 p50/p95、过期率与超时率。

### 5.2 性能问题的处理顺序

1. 分别测物理步、观测、核验、序列化、写盘、网络、模型和渲染耗时。
2. 去掉重复计算，降低无效更新，限制有界队列和回放缓存。
3. 使用适合碰撞的简化几何，保留清楚的机器人外形与接触显示。
4. 调整快照频率、网格细节和传感采样，记录受影响的观测语义。
5. 核对调整前后任务结果与评测定义，运行回归。

## 6. 视觉与交互验收

- 默认视角同时覆盖机器人、目标和主要障碍，提供总览与局部聚焦。
- 两个场景的单位、比例、地面、材质和照明一致，物体身份与任务目标容易辨认。
- 当前任务、当前计划步骤、当前动作、最近决策和异常状态有明确层级。
- 决策详情展示输入时间、候选、选择、过滤依据、监督结果和物理后果。
- 运行、暂停、复位、切换和导出都有接受、进行中、成功或失败反馈。
- 遮挡、过期、模型等待和能力未知在相关位置可见。
- 回放与实时运行显示明确身份，时间轴可跳到掉落、重规划和终态。
- 交互控件有键盘焦点、可读标签和足够对比度，关键状态同时提供文字。
- 对照页能从汇总指标进入具体差异事件，能力页能从结论进入原始试验。

新评审者按页面提供的操作指引完成任务。记录卡住的位置，修正界面或说明后再测。

## 7. 两条最终展示路径

### 路径 A 机械臂动态搬运

1. 打开默认场景，查看机器人、任务和能力来源。
2. 输入或选择搬运任务，核对目标、约束和计划。
3. 执行中移动方块，观察重新观察与局部调整。
4. 制造一次滑落，查看恢复、升级或终止。
5. 点开关键决策，检查输入、候选和实际结果。
6. 切换策略运行同一配置，查看差异事件和指标。
7. 打开能力图，追溯一项边界结论并运行一次探索试验。

### 路径 B 移动载货与跨形态复用

1. 切换到底盘场景，查看专用技能与共享策略。
2. 发起载货到点任务，观察车轮、车身与货物接触。
3. 加入临时障碍，观察等待、重新扫描或绕行。
4. 关闭一条通道或修改目的地，观察局部恢复和计划修订。
5. 查看共通决策、移动能力证据和机器人适配清单。
6. 打开两场景报告，分别解释任务结果和共享机制结论。

每条路径准备正常、恢复和失败配置，演示使用真实记录。短视频可剪辑运行片段，附原始运行 ID 和配置入口。

项目名称可以使用“跨机器人分层决策与能力探索仿真平台”。项目介绍说明研究问题、个人负责内容、机器人形态、关键机制、实验和局限。

以下简历表述为填写模板，方括号内用实际证据替换。

> 基于 MuJoCo 实现机械臂与差速搬运机器人的分层任务闭环，接入可替换决策策略、动态扰动、失败恢复与事件回放。在 [N] 个配对配置、[M] 个回合中评估 [机制] 对 [指标] 的影响，记录 [实测结果与区间]。实现基于 [变量] 的主动能力探索，并在独立条件中验证 [误差、覆盖或在线效果]。

- 画出从任务输入到真实动作、核验和下一轮决策的调用链。
- 修改一个场景参数并解释它通过哪些模块影响结果。
- 定位一次抓取或导航失败，给出可验证的修复方法。

- 说明接入第二机器人时复用、新增和修改的具体内容。

贡献说明写清个人技术决策、Agent 协助范围、第三方组件、复用源码与亲自验证内容。项目讲解围绕实际实现展开。

### G04 的具体检查方法

- 为至少一条 01 和一条 06 记录核对 schema、run_id、模型身份、状态、事件与终态，样本集合同时覆盖成功和失败。

- 关联一次浏览器命令的 command_id、epoch、监督回执、execution_id、事件与物理结果，检查重复与晚到命令。
- 运行既有 headless 固定配置与完整性检查。重执行按声明容差核对物理结果，模型随机性和实际耗时分别报告。
