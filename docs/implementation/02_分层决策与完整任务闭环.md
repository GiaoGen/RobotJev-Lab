## 1. 本阶段的问题与基本概念

把已有机械臂技能接入自然语言任务，并让每次动作根据新观测继续推进。

| 概念 | 本项目中的职责 | 学会后能解释的问题 |
|---|---|---|
| L3 规划 | 解析目标、生成步骤和约束，必要时修改剩余计划 | 为什么下一步需要抓取指定物体 |
| Harness | 结合当前步骤、观测和能力构造候选 | 当前有哪些可考虑的行动 |
| L2 判断 | 选择技能、等待、观察或升级 | 为什么现在执行这个候选 |
| L1 执行 | 使用 Panda 控制器完成动作 | 具体关节如何运动 |
| 执行监督 | 校验条件、预算、版本和硬约束 | 模型建议为什么被接受或拒绝 |
| 状态估计 | 保存可见、未知、过期和执行反馈 | 当前判断依据的信息是否仍可用 |

一次任务通常包含少量 L3 调用、若干事件触发的 L2 决策和持续运行的 L1 控制。三者调用频率分别记录。

## 2. 统一契约

### 2.1 机器人档案与能力

`RobotProfile` 保存机器人 ID、形态、传感来源、控制版本、基础技能和硬约束。Panda 档案包含工作空间、关节范围、夹爪宽度与当前支持的动作参数。

人工能力记录包含 `skill_id`、用途、参数范围、前置条件、结果定义、控制器版本、来源 `manual`、验证状态、证据列表和未知条件。已经完成 A02 的记录可以关联真实试验，状态按证据规则赋值。

### 2.2 观测示例

以下数字用于解释字段，实际运行写入实测值。

```json
{
  "observation_id": "obs-018",
  "run_id": "run-b01",
  "epoch": 2,
  "sim_time_s": 4.2,
  "sensor_profile": "simulated_state_sensor_v1",
  "objects": [{
    "id": "cube_red",
    "visibility": "visible",
    "position_m": [0.45, 0.10, 0.42],
    "observed_at_s": 4.2,
    "uncertainty_m": 0.005
  }],
  "robot": {"holding": "unknown", "active_skill": null}
}
```

对象被遮挡时，保留最后一次观测和时间，更新 `visibility`，当前位置设为未知或显式区分历史位置。置信度字段说明其计算来源，噪声模型和检测假设写入传感配置。

### 2.3 任务与计划

任务契约包含对象、目标区域、顺序要求、禁触对象、完成条件 ID 和可支持范围。完成条件引用程序中已定义的判定器。

计划包含 `plan_id`、版本、步骤 ID、步骤依赖、当前状态、已完成步骤、约束和修订原因。L3 返回的技能名、对象引用和参数必须通过本地校验。无法解析的目标通过 CLI/任务状态返回待澄清字段或不可执行原因。

### 2.4 决策请求与结果

```json
{
  "request_id": "decision-007",
  "run_id": "run-b01",
  "epoch": 2,
  "plan_version": 1,
  "observation_id": "obs-018",
  "capability_version": 1,
  "question": "选择当前搬运步骤的下一行动",
  "candidates": [
    {"id": "a1", "kind": "execute", "skill_id": "pick_top", "object_id": "cube_red"},
    {"id": "a2", "kind": "execute", "skill_id": "pick_alternate", "object_id": "cube_red"},
    {"id": "a3", "kind": "observe"},
    {"id": "a4", "kind": "wait"},
    {"id": "a5", "kind": "escalate"}
  ]
}
```

候选 ID 在请求内稳定。模型输出选择 ID、简短可核对的事实依据和可选分数。缺少概率来源时记录 `null`。模型自述分数带 `self_reported` 来源，校准实验另行评价。

## 3. 观测与真值的隔离

定义三个读取入口，分别提供 `Observation`、`VerificationState` 和 `RenderSnapshot`。L3、L2 和 Harness 的函数签名只接受前者及声明的能力记录。

状态传感器先读取仿真，再根据相机视野、射线遮挡、采样周期和噪声生成允许字段。最小实现使用少量对象采样点检查遮挡，并在配置中说明近似。对象 ID 来源于场景标签，报告记录该假设。

在线持物反馈模拟夹爪开度、接触和允许的载荷信号，标明可测来源。评测器保留真实物体位置、真实摩擦和隐藏参数。成功核验可以终结实验，给模型的下一步输入使用定义好的传感反馈。

泄露检查构造两个观测完全相同的世界，改变隐藏物体位置或未观测摩擦。发送给模型的输入应完全相同。原生观察读取显示状态，模型适配器由独立观测白名单序列化；07 工作台沿用相同权限边界。

## 4. 候选、策略与监督如何配合

### 4.1 Harness

按当前计划步骤枚举技能及观察、等待、升级。已知违反关节范围、夹爪宽度等条件的候选记录为拒绝，保存过滤前后列表与依据。能力未知时显示未知状态，并按实验模式配置决定是否允许受控尝试。

Harness 为每种策略提供相同的候选、可见状态和能力版本。场景中保留确有选择空间的决策点，例如调整接近方式与重新观察。只有一个可执行候选的事件单独统计。

### 4.2 规则基线

规则使用一份可阅读的优先表。硬约束触发暂停，信息过期时重新观察，已知失败时选择适用的替代技能，条件明确且可执行时执行，局部预算耗尽时升级。规则阈值在开发集校准后固定版本。

基础运行同时提供确定性的任务模板解析和规则规划器，将预设任务转换为同一 Task/Plan 契约。选择纯规则配置时，两场景可以在外部模型关闭的条件下完整运行。CLI 与事件记录展示解析与规划来源，模型实验则使用登记的 L3 配置。

### 4.3 模型策略与 L3

使用同一异步客户端接 L3 和 L2，分别提供任务 schema 与候选 schema。模型请求保存输入、输出、模型名、配置、耗时、供应商请求 ID、token 和可获得的成本信息。

第 2 周接通一个可用模型，第 6 周加入低延迟与通用模型的比较。模型响应经结构与语义校验后交给监督器，错误路径使用事件记录并呈现。

### 4.4 响应时效与执行前复查

响应必须匹配当前运行、epoch、计划版本、能力版本和候选集合。观测编号用于关联依据，实际应用还需检查对象位移、障碍变化、当前技能和观测年龄。

初始决策有效期可设为墙钟 3 秒，目标移动容差可设为 2 cm，具体数值通过试跑校准。每次物理步的普通状态更新继续进行，重要条件变化增加语义版本。模型等待期间机械臂保持已验证的稳定姿态，执行监督持续工作。过期响应触发新观测与有限次重试，超限后暂停。

## 5. 实施步骤

| 步骤 | 预计时间 | 操作与可观察结果 |
|---|---|---|
| 1 契约与传感 | 6 小时 | 建立 Pydantic 契约、档案和人工能力表，显示观测年龄与未知项 |
| 2 规则闭环 | 6 小时 | 固定合法任务经过 Harness、规则和监督驱动技能，保存任务终态 |
| 3 自然语言与 L3 | 5 小时 | 解析对象和约束，展示计划，运行缺对象、歧义、不可达任务 |
| 4 模型 L2 | 5 小时 | 同候选切换模型，完成异步请求、超时与非法输出处理 |

每一步完成后运行前一阶段固定搬运回归。开始模型调试前，先用规则跑通相同任务。

## 6. 一次任务的完整解释

用户输入“把红色方块放进 A 托盘，避开蓝色物体”。L3 解析到对象引用和禁触约束，生成接近、抓取、搬运和放置步骤。Harness 结合当前可见位姿和夹爪能力生成候选，规则或模型选择上方接近。监督器核对观测时效、路径和预算后创建执行。

技能通过位置执行器运动，模拟传感反馈确认持物状态。运行时推进计划，并在下一技能边界重新观测。放置后评测器检查真实位置、支撑与稳定窗口，保存终态。记录检查命令通过关联 ID 定位每次决策对应的输入、动作和后果，07 使用同一查询结果。

## 8. 故障定位与个人练习

| 现象 | 检查路径 |
|---|---|
| 模型选择合理但执行失败 | 核对执行时观测、参数转换、控制残差与物理反馈 |
| 两种策略总是相同 | 检查过滤前后候选、唯一候选比例和任务难度 |
| 遮挡后仍准确追踪物体 | 审核序列化白名单、历史字段和隐藏真值读取 |
| 模型等待导致卡死 | 检查事件循环、仿真线程、队列和客户端超时 |
| 计划跳过步骤 | 检查执行 ID、完成反馈和计划版本 |

亲自增加一个“重新观察后再抓取”的规则分支，用时间线解释差异。遮挡目标后查看模型实际输入。找到一个模型建议被监督器拒绝的例子，解释两层职责。
