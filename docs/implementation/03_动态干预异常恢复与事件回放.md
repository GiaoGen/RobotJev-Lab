## 1. 要解决的问题

系统需要理解“此前成立的条件已经变化”，并把处理范围控制在必要层级。小位移可以修正技能目标，路径阻塞可以切换局部路径，任务目标改变需要更新剩余计划，危险接触需要立即中止。

学习重点包括有限状态机、事件驱动、取消与幂等、仿真时间和墙钟时间、故障分类，以及从记录还原因果关系。

## 2. 三类物理干预与任务变更

| 干预 | 操作方式 | 期望路径 | 记录内容 |
|---|---|---|---|
| 目标位移 | 按钮或受约束拖动改变方块位置 | 停止使用旧目标，观察后调整或重试 | 移动前后位姿、触发步、观测到变化的时刻 |
| 路径障碍 | 将实体障碍移入通道或搬运路径 | 暂停、换局部航点，无法恢复时升级 | 障碍状态、候选变化、碰撞检查与实际结果 |
| 抓取滑落 | 对持物施加已记录的短脉冲外力 | 通过接触或持物反馈识别掉落，重抓或结束 | 力向量、持续物理步、接触与物体轨迹 |

另提供任务目标区域变更和目标移出可达区，验证 L3 修订与无法继续路径。直接改变位姿的干预标为操作者编辑，动力学扰动标为外力事件，两者均在运行记录中明确来源。

CLI、脚本与原生控制提交干预请求，仿真线程在固定步边界应用并返回回执。批量实验使用同一处理函数，07 浏览器接入同一命令链路。

## 3. 异常分级与预算

| 类别 | 示例 | 默认处理 | 初始预算 |
|---|---|---|---|
| 局部可恢复 | 小位移、单次空抓、临时障碍 | 观察、替代技能或重试 | 同一步骤最多 2 次恢复尝试 |
| 计划失效 | 目标区域改变、所有局部路径不可用 | 保存已完成步骤，L3 修订剩余计划 | 每任务最多 2 次重规划 |
| 硬约束或危险 | 禁触接触、关节越界、执行器异常 | 控制层停止或维持稳定姿态 | 优先立即处理 |
| 模型故障 | 超时、非法候选、连接失败 | 记录故障，执行配置中的安全暂停或显式规则回退 | 同一请求最多 1 次传输重试 |
| 无进展 | 多次等待、重复相同失败 | 重新观察、升级或结束 | 无进展仿真时间初值 10 秒 |

阈值统一放在运行配置。重复失败用步骤 ID、原因码和关键条件区间组成签名，避免数值噪声让计数无限重置。局部预算、任务预算和总时限同时生效。

任务状态采用 `ready`、`running`、`waiting_model`、`paused`、`succeeded`、`failed`、`cancelled`。技能状态采用 `pending`、`running`、`succeeded`、`failed`、`cancelled`、`timed_out`。状态转移集中在运行时，终态只能产生一次。

暂停期间停止物理步进与仿真时长预算，墙钟模型超时继续生效。恢复后重新验证有效条件。执行看门狗使用单调墙钟，记录操作者暂停与故障停滞的差异。

## 4. 取消、复位与晚到消息

1. 暂停或取消首先进入命令队列，并由控制层优先处理。
2. 当前技能执行可控的减速、保持或松开动作，具体方式按持物状态定义。
3. 更新执行状态，递增需要失效的计划版本或 epoch。
4. 模型请求尽力取消，晚到结果按请求身份检查并记录为过期。
5. 复位前将旧运行写入终态，新运行生成独立 ID 和清单。
6. 相同命令重复到达时返回既有回执，按钮和网络重试使用同一命令 ID。

紧急停止由仿真线程的监督逻辑处理，记录从接收命令到控制目标改变的物理步数和墙钟延迟。

## 5. 事件与回放

### 5.1 每次运行的文件

```text
runs/<run_id>/
  manifest.json          生效配置、版本、场景初始状态与种子
  events.jsonl           按序号记录任务、观测、决策、执行、干预与终态
  states.jsonl           复用 01 的实际状态记录，按声明的 schema 演进
  model.mjb              对应模型版本的编译场景，读取时核对环境
  model_requests.jsonl   可观测输入、原始响应与调用信息
  summary.json           指标、终态、完整性与异常说明
```

事件使用 `event_seq`、`step`、`sim_time_s`、`wall_time_utc`、单调耗时、`run_id`、`epoch`、`type`、`request_id`、`execution_id` 和负载。UTC 时间用于关联，耗时采用单调时钟。

快照至少保存 geom 位姿、关节状态、物体状态、活动技能和当前计划引用，目标采样约 20 Hz。重要事件附带关键快照。写入采用有界队列，记录队列压力，关键事件需要可靠落盘。发生磁盘满或记录故障时暂停运行并通过 CLI/原生状态反馈原因。现有 record_schema_version=1 的事件 type、状态字段和模型文件按实际代码核对，升级时记录兼容读取与迁移策略。

### 5.2 回放语义

本阶段提供按 run、步编号/时间或事件查询的检查入口，使用真实状态在原生查看器或离线脚本中重建关键时刻，关联原运行 ID 和证据。07 增加浏览器播放、拖动时间轴与决策详情，复用当前读取器和事件检索。

另提供按原配置重新执行的入口，注明物理版本和模型随机性造成的可能差异。回放记录与重新执行各自生成明确身份和证据。记录缺口写入完整性汇总，07 将其呈现到时间轴。

## 6. 同条件对比

第 3 周交付基础成对运行器。它从一份初始状态清单启动规则和模型两次运行，固定机器人、控制器、能力版本、传感配置和扰动定义。

干预支持两种预先登记的触发方式。

- 固定仿真时刻，适合评价相同时间的外部变化。
- 语义事件触发，例如首次确认持物后第 N 步，适合让两策略面对相近任务阶段。

记录触发类型、实际触发时刻和触发是否发生。未到达触发阶段的回合保留原终态，并标记未触发。展示所有回合结果及实际触发子集。

基础指标包含成功、总仿真时间、总墙钟时间、模型等待、恢复成功、重规划、约束拒绝、碰撞、决策延迟和成本缺失状态。文档 06 扩展完整统计。

## 9. 故障定位与个人练习

| 现象 | 优先检查 |
|---|---|
| 目标移动后仍按旧路径抓取 | 响应时效、语义版本和执行前位移复查 |
| 系统无限等待 | 无进展计时、等待动作结束条件和总时限 |
| 升级后已完成任务重做 | 完成历史和剩余计划的合并规则 |
| 回放顺序混乱 | 单写入顺序、事件序号、仿真时间与墙钟时间 |
| 策略对比扰动不同 | 初始清单、触发规则与未触发状态 |
| 复位后机器人突然动作 | epoch、旧执行取消和旧响应拒绝 |

亲自修改一次恢复预算，解释终态为何变化。复位时故意延迟模型响应，检查其如何被识别为过期。任选一个失败，从触发、观测、候选、选择、执行和核验六个节点复盘。

交接时提供完整 M1、故障注入记录、成对运行配置、事件 schema 和一次失败讲解。下一阶段使用同一记录与执行入口组织探索试验。
